Introduction
1.	Bridge is used when we need to decouple an abstraction from its implementation so that
	the two can vary independently. This type of design pattern comes under structural 
	pattern as this pattern decouples implementation class and abstract class by providing
	a bridge structure between them.

2.	This pattern involves an interface which acts as a bridge makes the functionality of
	concrete classes independent from interface implementer classes. Both types of classes
	can be altered structurally without affecting each other.

3.	We are demonstrating use of Bridge pattern via following example in which a circle can
	be drawn in different colors using same abstract class method but different bridge
	implementer classes.



Implementation 
1.	We have a IDrawAPI interface which is acting as a bridge implementer and concrete classes
	RedCircle, GreenCircle implementing the DrawAPI interface. Shape is an abstract class and
	will use object of DrawAPI. Program, our demo class, will use Shape class to draw different
	colored circle.



Required Steps for Implementation
Step 1: Create bridge implementer interface: IDrawAPI.cs
Step 2: Create concrete bridge implementer classes implementing the DrawAPI interface: RedCircle.cs,
		GreenCircle.cs
Step 3: Create an abstract class Shape using the DrawAPI interface: Shape.c
Step 4: Create concrete class implementing the Shape interface: Circle.cs
Step 5: Use the Shape and DrawAPI classes to draw different colored circles: Program.cs
Step 6: Verify the output.
